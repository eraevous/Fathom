# 026 — A clearer Fathom front door

Proposed for Zach in response to the November 9, 2026 request for a branded landing page, README, polished UI and bug-fix iterations. Implementation is authorized; usefulness and brand acceptance remain Zach’s.
Serves: P0@2, DG-RA@1, DG-RB@1, DG-RE@1, DG-RF@1, DG-A1@1, FT-BRAND26-R1@1.

## US1 — Understand the tool before installing (P1)
A newcomer can read a branded, offline-capable landing page and concise README to learn what Fathom does now, what it does not do, and how to run a synthetic example. Detailed existing usage remains available. Local reruns, panels and current commands replace stale no-server/single-wide-only claims. Links resolve without assuming a deployed website or PyPI package.

## US2 — Read a polished, trustworthy report (P1)
Retain the existing Kairos tool palette, finding semantics and report order while improving report/configurator hierarchy, spacing and brand identity. Add small useful progressive enhancements only where they help navigation or readability. Keyboard, narrow screens, dark mode, reduced motion, printing and scripts-disabled operation remain usable. No data-dependent inference or threshold changes.

## US3 — Validate rather than merely decorate (P1)
Synthetic profiles remain byte-deterministic and artifact-derived; HTML never fetches resources. Regression tests protect escaping, real link targets, progressive fallback and control reset/repeated-use behavior. Verify representative desktop and mobile screens and run the full suite. Record findings, misses and limitations.

## Boundaries
No hosting, deployment, accounts, analytics, remote assets, new runtime dependency, data upload or data modification. No fabricated capability or accepted requirement. The MtG intake request is a separate slice; it must not be advertised as implemented here. No archived Data Guide implementation is consulted.
